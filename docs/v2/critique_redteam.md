# Critic #1: red-team review of PLAN_v0_draft.md

Scope: an attacker who holds the Wi-Fi PSK (any LAN guest, or a compromised IoT device), plus an attacker on the WAN or upstream network. The target is v2 exactly as drafted.

Labels:
- **Verified** means tested this session: nft 1.0.9 run in an unprivileged netns, or a primary-source document read.
- **Reasoned** means it follows from the design or the code but was not executed.

Severity scale: Critical, High, Medium, Low.

## Verified nft facts that change the design

- **V1. A chain named `fwd` is a syntax error.** `fwd` is a reserved keyword, so name chains `forward_gate` or similar. The draft's dynamic-set syntax is otherwise valid. `add @newconn_meter { ip saddr limit rate over 100/second burst 200 packets } add @flood_offenders { ip saddr } drop` loaded and listed correctly. (Verified)
- **V2. A full dynamic meter fails open.** With `size 4`, keys 5–10 were never rate-limited: all 3 packets each got through, and only keys 1–4 were policed. A random- or many-source flood that fills `newconn_meter` therefore escapes the meter completely. (Verified)
- **V3. `ct state new` meters miss floods against a service that replies.** I sent a single-5-tuple UDP flood to a non-responding port: 18 of 20 packets were dropped, because the flow stays NEW until a reply is seen. The same flood to an echoing responder: 0 of 20 dropped. After the first reply the flow is ESTABLISHED and never matches again. Real cases: dnsmasq on :53 (the UDP flood in the attack lab), the portal on :8080, or a WAN host that answers (an iperf/echo/game server). (Verified)
- **V4. Every rule shape the fixes below rely on loads cleanly in nft 1.0.9 (Verified):**
  - `fib saddr . iif oif missing drop` at `priority raw`
  - `iifname . ip saddr . ether saddr @allow_bound`
  - an ARP-family `arp saddr ip . arp saddr ether != @macbind drop`
  - `add @conc { ip saddr ct count over 20 } reject`
  - per-MAC DHCP meters: `add @dhcpm { ether saddr limit rate ... }`
  - `meta nfproto ipv6 iifname "wlan0" drop`

## Findings

| # | Attack | Sev | Stopped by v0? | Fix | Label |
|---|---|---|---|---|---|
| 1 | **Intra-BSS (client-to-client) traffic never reaches netfilter.** On a Wi-Fi AP with isolation off (the default), station-to-station frames are bridged inside the AP stack/driver or firmware and never hit `forward`. Scanning, brute-forcing or exploiting a neighbour or an IoT device is invisible and unenforceable. ARP-spoof MITM of other clients works the same way. The v1 attack lab only targeted the Pi, so this never showed up. | **Critical** | No | Enable AP isolation (`802-11-wireless.ap-isolation yes`, NM AP-mode property) so every L2 path goes through the Pi. Decide explicitly: either clients can't talk to each other at all (fine for an IoT/guest LAN), or the Pi hairpins intra-LAN traffic at L3 with proxy-ARP plus `forward` rules so it's both visible and enforceable. Test on the Pi that brcmfmac honours isolation. Add a test that sends client A→B with capture on and confirms the Pi sees it. | Reasoned (the NM property is documented: networkmanager.dev) |
| 2 | **The allowlist bypasses anti-spoofing.** The draft puts `allow4 → return` first and builds allow4 from IPs (admin PC, Pi, gateway). A LAN client that sends with `ip saddr = 192.168.101.2` (admin PC) or the upstream gateway's IP skips every meter and block. The base ruleset already has `ip saddr ${ADMIN_PC_IP} tcp dport {22, API_PORT} accept` **with no `iifname`**, so admin-port reachability is decided by a spoofable IP alone. | **Critical** | No (made worse) | Strict order at `prerouting priority raw`: (a) `iifname LAN fib saddr . iif oif missing drop` (reverse path); (b) drop LAN-ingress sources outside `protected_network`; (c) the IP↔MAC check; only then (d) allowlist matched on `iifname . ip saddr . ether saddr` (`allow_bound`). Pin the admin to `iifname eth0` plus its MAC in both base.nft and `enforce_admin_pc_ip`. | Verified (syntax and base.nft text); Reasoned (exploit) |
| 3 | **Meter exhaustion lets everyone through** (V2). Fill `newconn_meter`, `flood_offenders` or `pps` with distinct keys, then flood freely. Also, Python `add element` to a full `block4` (size 4096) fails, so the real attacker can't be blocked. | High | No | Anti-spoofing first (limits distinct source IPs to leased clients). Size each meter to at least 2× the DHCP pool. Add a **global, keyless backstop** per interface and hook (`iifname wlan0 ct state new limit rate over N/second drop`, plus a pps backstop). Alert when a set is above 80% full (core polls `nft list set` counts). Treat a failed add as CRITICAL and fall back to a coarser action. | Verified (V2); Reasoned (rest) |
| 4 | **Floods against services that reply evade the meters** (V3). Examples: a UDP flood to dnsmasq:53, an HTTP/TCP data flood on one established connection to the portal, upload saturation to a responding WAN host. | High | No | Add meters that ignore conntrack state: a per-source pps meter on `input` (`add @pps_in { ip saddr limit rate over 500/second }`), per-service meters (DNS queries/s per source, `ct count` concurrent connections to :8080/:443). Add a per-source byte-rate RATE_LIMIT for forwarded upstream traffic, tuned from the benign capture. Action is RATE_LIMIT, not drop, to protect G5. | Verified (V3) |
| 5 | **The macbind design blackholes or fails open, and is weak to MAC churn.** "Drop if not in macbind once that client has a lease" can't be written as one rule. The obvious `ip saddr . ether saddr != @macbind drop` blackholes static-IP devices (printers) and **every new client whenever the binding feeder lags or pirewall-core is down**. That breaks fail-open and G6. dnsmasq runs `dhcp-script` **serially, one instance at a time** (man page), so a burst of DHCP from many MACs queues the bindings: a DoS for new joiners. | High | Partially | Two-tier rule: `ip saddr @bound_ips ip saddr . ether saddr != @macbind drop` (anti-impersonation, safe for new clients), plus `ip saddr != @bound_ips` → a tight "unbound" meter class and MONITOR. Feed bindings from a tiny **separate** unit that watches the NM dnsmasq lease file read-only (inotify), *not* from core, so it keeps working when core is dead. Add static bindings from the allowlist. | Verified (dnsmasq semantics); Reasoned |
| 6 | **The `dhcp-script` helper is a new root-level, attacker-fed input.** It runs **as root by default** (`--dhcp-scriptuser`). The hostname, vendor class and client ID are client-supplied (`DNSMASQ_SUPPLIED_HOSTNAME`, …). Shell use, log injection (newlines into Wazuh syslog) or an RPC that reaches `core.sock` would hand a DHCP packet a path to the kill switch. | High | No | Prefer the lease-file watcher (#5). If a script is used: `dhcp-scriptuser=pirewall-lease`, read only `$1 $2 $3` (action, MAC, IP), validate them with regexes, ignore every env var, write to a dedicated one-method socket (`bind_lease`) that is **not** `core.sock`, and escape the hostname before any log. | Verified (man page) |
| 7 | **Framing a neighbour is still possible.** (a) MAC cloning while the victim is offline gets the victim's IP from DHCP; misbehave, and the victim inherits the IP-keyed block on return. (b) After lease expiry the IP is reissued to someone else, who inherits the block. (c) With WPA2-PSK, an attacker who sniffed a victim's 4-way handshake can derive the victim's PTK and **inject frames as the victim's MAC**, which defeats macbind entirely. | High | No | Key blocks by **MAC (and portal account when the portal is on)**, not IP. Purge or re-key IP entries on DHCP del/add. Short initial TTLs with backoff (already planned). Move to WPA3-SAE (forward secrecy defeats (c)) where the clients and brcmfmac allow it. Document (c) as a residual risk on WPA2-PSK. | Reasoned |
| 8 | **MAC churn resets reputation and starves DHCP.** A new randomised MAC means a new identity, a fresh TTL backoff and a fresh meter bucket. Thousands of MACs exhaust the /24 pool (NM shared mode), and later the macbind and meter sets. | High | No | `max_num_sta`/client cap on the AP; a per-MAC DHCP meter (`udp dport 67 add @dhcpm { ether saddr limit rate over 5/second }`); an alert when new MACs per minute rise. With the portal on, escalate per **account** (credentials can't be churned). Treat many new MACs per minute plus throttled DHCP as its own D1 detector. | Verified (syntax); Reasoned |
| 9 | **nDPI/NFStream in the privileged process means a parser RCE becomes firewall control.** nDPI has a history of remote memory-safety bugs in its dissectors (e.g. CVE-2020-15473, a heap over-read in the OpenVPN dissector, CVSS 9.1). The draft runs NFStream inside pirewall-core, which holds `CAP_NET_ADMIN`. A crafted packet that crashes it also triggers fail-open and the crash-loop limit (v1 #17). | High | No | Run capture/NFStream as a **separate unit** (`pirewall-sensor`, only `CAP_NET_RAW`, no NET_ADMIN, seccomp, `MemoryMax`, no access to the RPC sockets except a write-only flow socket). Core consumes the flow records. Pin the NFStream/nDPI version, set `n_dissections` low, and restart the sensor freely: a sensor crash costs visibility, not enforcement. | Verified (CVE); Reasoned |
| 10 | **Blinding the sensor and then attacking.** Saturate libpcap/NFStream with traffic *just under* the kernel meters from 2–3 devices (or one device on the established-flow path, #4). While the Pi CPU is pegged, run the real scan or brute force. D1/D2/D3 never see it, and only the kernel plane acts. | High | Partially | Put the cheap, critical detectors **in the kernel**: closed-port hits on `input` (`add @closed_hits { ip saddr limit rate over 20/second }` before the policy drop), RST/ICMP-unreachable reply meters, a per-source SYN meter. Export libpcap/NFStream drop counters; above X% raise SYSTEM_WARNING and switch the policy into a conservative mode where kernel meter offenders are RATE_LIMITed directly. Use a BPF capture filter (drop the bulk of established payload, keep SYN/FIN/RST and the first N packets) to cut the sensor's load. | Reasoned |
| 11 | **Poisoning the benign soak.** The thresholds come from "the benign capture's P99.9", and the user is running attack-lab traffic and capturing benign in the same 42 h. Any attacker or compromised IoT device on the LAN during the soak (or the user's own lab traffic leaking into it) inflates the quantiles and trains the anomaly model on attacks. A patient attacker runs slow scans throughout. | High | No | Capture benign **per MAC with time-window labels** and exclude the attacker/lab MACs and windows. Have the attack lab use a dedicated MAC with timestamps logged. Clamp learned thresholds: `threshold = min(P99.9 × margin, hard_ceiling)` from security priors (e.g. >100 distinct dst ports in 60 s is never benign). Run a sanity pass that flags hosts in "benign" exceeding any ceiling. | Reasoned |
| 12 | **Low-and-slow and distributed attacks sit under every per-source window.** Examples: nmap `-T1/-T2` with randomised order and source ports; brute force at 1 attempt per 30 s; several compromised devices each under threshold attacking one victim. | Medium | Partially (slow scans "within 60 s" only) | Long-horizon counters (1 h/24 h distinct dst ports and hosts per MAC; cardinality sets with long timeouts) → MONITOR. Fan-in detectors keyed by **destination** (many sources → one victim) and by service (auth failures per account across sources). The portal throttle must be per account and global, not only per IP (`max_failed_logins_per_ip` today). | Verified (config); Reasoned |
| 13 | **IPv6 and non-IPv4 bypass the whole v2 table.** In an `inet` table, IPv6 packets never match `ip saddr …` rules and fall through to `policy accept`. If anyone rebuilds the AP with NM's default `ipv6.method auto`, or clients reach each other over link-local (see #1), v2 sees nothing. | Medium | No (documentation only) | Make it explicit in the v2 table: `meta nfproto ipv6 iifname LAN drop` on input/forward (verified syntax) unless v6 is supported. Run a startup self-check that `disable_ipv6=1` on the LAN interface and refuse ACTIVE mode otherwise. | Verified (syntax); Reasoned |
| 14 | **Fragmentation evades the sensor.** The kernel defragments before conntrack (and before `raw` filters), so nft rules see whole datagrams. libpcap/NFStream sees **raw fragments**, and non-first fragments carry no ports, so features and early-packet sequences are wrong. A fragment flood also burns defrag memory and CPU. | Medium | No | Drop LAN-ingress fragments unless a real need exists (`ip frag-off & 0x1fff != 0 drop`, plus the MF bit) since home clients have PMTU discovery. Count fragments per source as a D1 signal. | Reasoned |
| 15 | **Evading D3 (supervised) and D2 (anomaly).** Pad or jitter flows (TANTRA-style), tunnel over QUIC/HTTPS to a CDN-fronted C2, use ECH (no SNI for nDPI), randomise the JA4 via a uTLS client. | Medium | Yes, by design (D3/D2 alone only MONITOR) | Keep D3/D2 as evidence-only. That's the right call: evasion costs visibility, not safety. Don't spend the 42 h fighting ML evasion. | Reasoned |
| 16 | **Encrypted C2 and exfiltration.** Low-rate HTTPS beaconing, DoH/DoT to public resolvers (bypassing the Pi's DNS), DNS tunnelling through the Pi's dnsmasq. | Medium | No | Force DNS: redirect or block LAN→WAN udp/tcp 53 and 853 except via the Pi, and flag connections to known DoH endpoints. Add a DNS tunnelling detector on dnsmasq query logs (label length, entropy, NXDOMAIN rate, queries/min per MAC). Add a beacon-periodicity detector (v1 had `temporal_pattern`) and an upload-volume anomaly per MAC per hour. Declare payload/C2 content out of scope in the paper. | Reasoned |
| 17 | **Turning the policy against the operator.** (a) The admin PC IP is spoofable (#2). (b) If the admin ever joins over Wi-Fi, a MAC clone of the admin gets the admin's MAC blocked. (c) The **kill switch / `revert_to_base` must not delete the kernel plane.** The draft says it "flushes block4/ratelimit4", but if it drops the table, a crash (fail-open) also removes anti-spoofing and meters, and G6 fails. | Medium | Partially | The admin path is interface-plus-MAC bound and on its own interface (eth0), and is never subject to LAN policy. The validator refuses targets in `allow_bound` *and* the admin MAC. Split the v2 table into `pirewall_static` (anti-spoof, meters, backstops: never touched by core or kill switch) and `pirewall_adaptive` (sets the kill switch flushes). Test: kill core and confirm the meters still drop. | Reasoned |
| 18 | **Static meter thresholds cause self-DoS.** 100 new connections/s per source with burst 200 is exceeded by BitTorrent, some game consoles, a phone restoring a backup, or a browser on certain pages. A `drop` there breaks G5 (0 benign RATE_LIMIT/BLOCK). An attacker can also *trigger* it for a victim if spoofing were still possible. | Medium | No | Kernel meters RATE_LIMIT (police) rather than drop. Thresholds come from the benign capture's per-MAC maximum × 3, with ceilings. Allowlisted heavy devices get their own meter class. Measure the FP rate on the held-out benign capture before ACTIVE. | Reasoned |
| 19 | **Portal and API weaknesses that remain.** Plaintext portal credentials are readable by any PSK holder who has the victim's handshake (#7c). Portal login throttling is per IP only. Portal slowloris on :8080 (no concurrency cap). If the API process is compromised, `add_allowlist_entry` allowlists the attacker. | Medium | Partially (v0 adds an admin throttle and (ip, mac) binding) | `ct count over 20` per source on :8080 (verified syntax). Per-account and global portal throttles. Allowlist additions through the API require re-entering the admin password and are limited to /32 plus MAC with a reason; they emit a Wazuh alert. State plainly that the portal is a usability gate, not confidentiality (v1 C5). | Verified (syntax); Reasoned |
| 20 | **Wi-Fi layer: deauth, evil twin, PMF.** The draft says "hostapd `ieee80211w=2`", **but the deployment's AP is NetworkManager shared mode** (`setup-new-network.md` §AP), which drives wpa_supplicant's AP mode, not hostapd. The relevant knobs are `802-11-wireless-security.pmf` and `key-mgmt sae`. On a Pi, AP-mode SAE plus `ieee80211w=2` has been reported working **under hostapd** with brcmfmac (hostap list, 2024). Under NM/wpa_supplicant AP mode it's unverified. PMF only protects PMF-capable clients, and `pmf=required` locks out old IoT devices. Evil twins bypass the Pi entirely. | Medium | No (wrong component) | On the Pi in hour 0–2: try `nmcli … wifi-sec.pmf required` (or optional) and `key-mgmt sae`, and if that fails switch the AP to hostapd. Accept `pmf optional` if IoT devices break. Declare deauth/evil-twin **detection** out of scope for 42 h (needs a monitor-mode radio; nzyme-style counting). Never claim deauth detection in the paper without it. | Verified (thread and repo docs); Reasoned |
| 21 | **Upstream (WAN-side) attacker.** The uplink is a shared Wi-Fi or campus network. A rogue DHCP server or ARP spoof upstream changes the Pi's gateway or DNS. `network_drift` only warns. Plain DNS forwarding by dnsmasq is poisonable upstream. | Low–Medium | No | Pin the upstream gateway MAC after first boot, and alert on a change of default gateway MAC. Optional DoT upstream (unbound/stubby) is out of 42 h scope; document it. The WAN `input` surface stays tiny (udp 68 only): keep that. | Reasoned |
| 22 | **Set and state exhaustion on the sensor side.** NFStream's flow cache and the D1 per-source dictionaries grow with flows and MACs. A many-flow attack forces evictions or OOM. That's a sensor crash, not an enforcement failure, if #9 is done. | Low | Partially | Bounded caches with counters for evictions. The sensor has its own `MemoryMax` and restarts freely. | Reasoned |

## What v0 gets right (keep)

- Moving enforcement into kernel sets with timeouts, and keeping kernel protection alive when Python dies (G6). The split in #17 is required for this to hold.
- Making D3/D2 evidence-only while D1 can act. This is the correct response to ML evasion.
- Using one exporter for training and live.
- A scripted, logged attack lab (G7). Also add the intra-BSS (#1), spoof-the-admin (#2), meter-fill (#3), established-flow flood (#4), MAC-churn (#8) and slow-scan (#12) cases as **explicit test cases**. v1 never tested any of them.

## Explicit scope exclusions to state in the paper and README

Payload/C2 content, ML evasion by shaped traffic (beyond MONITOR), deauth/evil-twin detection (no monitor radio), WPA2-PSK insider decryption and injection (WPA3 only fixes it partly), IPv6 (blocked, not analysed), and upstream DNS integrity.
